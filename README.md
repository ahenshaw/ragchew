# js8

A pure-Rust encoder and decoder for **JS8**, the weak-signal digital mode used
by [JS8Call](https://js8call.com) for keyboard-to-keyboard HAM radio messaging.
This is the codec library; a GUI application will be built on top of it.

Implements the JS8 **Normal** submode end to end:

```
text ──varicode──▶ 72-bit payload ──+itype──▶ 75 bits ──+CRC-12──▶ 87 bits
     ──LDPC(174,87)──▶ 174 bits ──recode──▶ 79 × 8-FSK symbols (3 Costas sync)
     ──continuous-phase FSK──▶ 12 kHz audio
```

and the reverse: spectrogram sync search, FFT tone demodulation (with **sub-bin
frequency** tracking), soft-decision LLRs, and belief-propagation LDPC decoding.

## Status

- ✅ Encoder — bit-exact with the reference (message bits, LDPC codeword, symbols).
- ✅ Decoder — free-text (varicode), heartbeat/CQ, directed, and (s,c)-dense frames.
- ✅ Validated on synthetic round-trips, additive noise, and **real off-air audio**.
- ⬜ GUI application (planned).

## Usage

```rust
use js8::message::IType;

// encode
let audio = js8::encode_freetext("HELLO WORLD", IType::None, 1500.0); // Vec<f32> @ 12 kHz

// decode a single known-frequency signal
let msg = js8::decode_near(&audio, 1500.0, 0).unwrap();
assert_eq!(msg.text(), "HELLO WORLD");

// decode every frame in a real recording across a band
let (samples, _rate) = js8::wav::read("recording.wav").unwrap();
for r in js8::modem::decode_all(&samples, 300.0, 2600.0, 30) {
    println!("{:.1} Hz  t={:.2}s  {}", r.hz, r.offset as f64 / 12000.0,
             js8::message::unpack(&r.a87).text());
}
```

### Example CLI

```
cargo run --release --example js8_tool -- encode "CQ CQ DE KN4CRD" out.wav 1500
cargo run --release --example js8_tool -- decode recording.wav
```

(WAV must be 12 kHz mono 16-bit PCM; transcode with
`ffmpeg -i in.mp3 -ac 1 -ar 12000 out.wav`.)

## GUI (in progress)

A panoramic multi-channel monitor — a waterfall plus inline decoded text for
every conversation in the band — is being built in the `gui/` workspace member
(`eframe`/egui). Design: [`docs/design/waterfall-ui.md`](docs/design/waterfall-ui.md).
The `js8` library stays UI-free; the app depends on it.

```
cargo run -p js8-gui --release -- --live                 # live: decode the default audio input
cargo run -p js8-gui --release -- recording.wav          # play back a recording (needs a display)
cargo run -p js8-gui --release -- --demo                 # synthetic multi-station band
# headless validation (no windowing/audio stack) — dumps PNGs:
cargo run -p js8-gui --no-default-features --release --example render_png -- recording.wav out.png
cargo run -p js8-gui --no-default-features --release --example scene_png -- scene.png
```

Working: shared-axis waterfall, full-band decode, channel tracking across cycles,
the text panel with nudge layout + horizontal–diagonal–horizontal leader lines,
frequency zoom/pan (wheel/pinch/scrollbar) + text-size control, scroll-in
animation, **live audio capture** (`cpal`, auto-resampled) with a device picker
and a cycle-aligned decode loop, and **automatic per-channel submode detection**
(Slow/Normal/Fast/Turbo decoded simultaneously, each channel colored by its mode).

The codec supports all four submodes (`js8::submode`, `decode_all_multi`); they
share the LDPC/CRC/varicode chain and differ only in symbol timing, tone spacing,
and Costas arrays. Detection is per-signal: each submode's sync is searched
independently and the CRC gate rejects wrong-mode guesses.

The pure rendering/layout pieces (`waterfall`, `layout`, `scene`, `colormap`,
`channels`) have no windowing dependency, so they're unit-tested and validated
by rendering to PNG without a display.

## Architecture

| Module | Responsibility |
|--------|----------------|
| `varicode` | Free-text Huffman pack/unpack |
| `message`  | Frame assembly/parsing (CRC, itype, callsign/grid, dense word list) |
| `crc`      | CRC-12 (`0xc06`, JS8 `^= 42`) |
| `ldpc`     | LDPC(174,87) encode + sum-product decode |
| `modem`    | 8-FSK synthesis; sync search, FFT demod, sub-bin search, soft LLRs |
| `tables`   | Generator / parity / Costas constants (generated by `tools/gen_tables.py`) |
| `wav`      | Minimal 16-bit PCM mono WAV I/O |

## Performance

Single core, `--release`, on a 12 kHz recording:

| Workload | Audio | Wall | vs real-time |
|----------|------:|-----:|-------------:|
| Encode | 12.6 s/frame | 1.8 ms | ~6,900× |
| Decode 1 cycle, 300–2600 Hz | 15 s | 0.7 s | ~22× |
| Decode full recording, 300–2600 Hz, 9/9 | 134 s | 3.9 s | ~35× |

The decoder builds one magnitude spectrogram, then decodes candidate frames
directly from it (no per-candidate FFTs), filtering with a cheap hard-decision
parity check before running full belief-propagation. For reference, Robert
Morris's `fate` decoder (FFTW + OSD) on the same file runs ~1.9× real-time.

## Validation

Correctness is checked against Robert Morris (AB1HL)'s independent JS8
implementation ([`fate`](https://github.com/rtmrtmrtmrtm/fate)); see `tools/ref`.

- `tests/reference.rs` — every stage (message bits, LDPC codeword, 79 symbols,
  unpacked text) is **bit-for-bit** identical to the reference across a set of
  frames, plus a clean audio round-trip and decoding a reference-synthesized WAV.
- `tests/noise.rs` — decodes correctly through additive white Gaussian noise well
  below the signal level (soft-decision LDPC path).
- `tests/real_audio.rs` — decodes a real 9-frame off-air recording (John 3:16,
  drifting ~1390 Hz carrier). This crate and the reference decoder both recover
  **9/9 frames**, character-identical.

```
cargo test --release
```
